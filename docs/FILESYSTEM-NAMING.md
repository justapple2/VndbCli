# 本机目录名兼容规则

目录名使用兼容别名，VNDB原名、会社、条目ID和个人记录保留原文。只改完整容器的外层目录，不改EXE和内部资源。

| 原文／当前名称 | 新建目录的兼容名称 |
| --- | --- |
| `サンプル♥ゲーム ～追加篇７～` | `サンプルゲーム 追加篇7` |
| `ゲーム★☆†♪` | `ゲーム` |
| `会社：テスト／ブランド` | `会社 テスト ブランド` |
| `サンプル ＋PLUS 追加編` | `サンプル PLUS 追加編` |
| `ゲーム＋` | `ゲーム PLUS` |

生成目录采用Unicode兼容归一化和白名单：文字、数字、ASCII空格／连字符／下划线。装饰符号和不可见标记清除；标点作为分隔。商标符号不生成额外品牌词，`+`与`×`等有含义的标记分别保留为`PLUS`、`x`；不自动截断长名。显式目标根允许`Program Files (x86)`这类系统目录中的普通ASCII括号和句点，其余符号需换一个兼容目标根，程序不改名系统目录。

扫描JSON保留真实`path`，额外提供`suggested_name`及`name_needs_review`。核对中只有兼容名一致且当前名称已兼容时才视为已整理；`ゲーム♥`可以提示清理为`ゲーム`，已叫`ゲーム`的目录不会再加回爱心。兼容名称仅是本机路径别名，不能作为新的VNDB唯一匹配凭据；作品关联、查询文字、会社原名、评价和条目ID不变。

清理后有同名目录或多条计划指向同一目标时，全部标记冲突；不加不明后缀、不合并、不覆盖。既有兼容会社目录保持原大小写／字宽，含符号的默认会社目录先整体核对；版本／特典文字和多组件合集不能因清符号被截掉或拆开。不会改EXE、资源、内部目录、注册表或工具配置。

已有关联作品的日文发行版本名也会保留，即使它与基础作品的日文标题不同。发行资料尚不完整时仍需人工核对版本，不能把同一 VNDB 作品下的不同发行版统一改成基础标题。

新的执行及未改名的旧意图在rename前拒绝不兼容目标。旧任务若已移动，可以先完成原证据回执；复原仍须明确批准，并回到原路径，即使该历史路径含符号。原计划与日志不改写，后续需要清理时另建安全计划，不能破坏复原能力。

去符号不保证所有旧引擎、编码、注册表或转区依赖都能正常运行；必要时明确选择简短ASCII目录别名并单独核对。整理与复原操作见[桌面](DESKTOP.md#8-目录整理与复原)和[CLI](CLI.md#6-本机登记与整理工作流)。
