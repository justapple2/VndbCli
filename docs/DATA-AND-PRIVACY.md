# 数据位置、隐私与备份

Web 保存完整资料库；桌面与 CLI 只使用本机 JSON。程序目录、客户端数据根和服务端数据卷分离，更新程序不更换已有身份。

## 服务端数据

| 内容 | 默认宿主相对位置 |
| --- | --- |
| 公共作品、会社、发行目录、个人条目、评价与时间 | `data/library.db` |
| 已缓存封面 | `data/covers/` |
| 稳定服务身份 | `data/service-instance-id` |
| 官方原包及任务输入 | `data/datasets/` |
| 维护预览与恢复意图 | `data/dataset-cleanups/` |
| 完整快照 | `data/backups/` |
| 应用管理密钥 | 独立 `secrets/library_write_key`，只读挂载 |

实际宿主位置由 Compose 决定，容器中数据根为 `/data`。SQLite 使用 NAS 本机卷，客户端经 HTTP API 访问，不直接通过共享文件夹写库。

Web 只接收准确个人条目及设备的存在布尔值，不保存客户端绝对／相对游戏位置、EXE、参数、包清单、组件目录树、注册表或移动证据。封面 URL 是服务自身资源，与本机游戏位置不同。公开资料、个人数据和存在状态分别管理，导入公共库不会自动创建游玩经历。

## 客户端数据

默认根为系统解析的“文档”下 `VndbLocal`，`VN_DESKTOP_HOME` 可覆盖。不要按用户名拼接路径；查询根覆盖只改变查询数据，不搬迁设备或启动配置。连接配置优先级见 [CLI](CLI.md#2-连接配置与数据根)。

| 内容 | 数据根中的位置 |
| --- | --- |
| 设备身份 | `device.json` |
| 桌面设置／CLI 配置 | `desktop-settings.json`／`client.json` |
| 安装、组件、安装包及条目关联 | `local-library.json`；明确迁移后为 `local-library.v2.json` |
| 迁移后按摘要保存的作品资料 | `local-metadata/` |
| 启动程序、参数及工作目录 | `launch-profiles.json` |
| 观测设置／派生快照 | `observation-settings.json`／`local-observations.json` |
| 本机资源档案 | `local-resources.json` |
| 整理／复原记录 | `archive-runs/`、`organization-state/` |
| 注册表／引擎修复备份 | `registry-repairs/`、`engine-path-repairs/` |
| 查询缓存、按需详情、个人离线稿、分类及回执 | `servers/<服务地址摘要>/`；无服务时为独立 offline 作用域 |
| 最近一次启动诊断 | `startup-diagnostics.json` |

安装包与资源以检索根及相对位置登记，只作为本机资源；文件名只是候选，不证明作品版本、完整性或可启动。已确认缺失与根不可读等“未知”状态分开，任何一个准确登记的安装或包存在都可形成已有标记。

查询导出 JSON 可按格式提交 Web；本机扫描报告、完整数据根、命令预览、修复备份及移动回执不能上传。目录历史页和详情缓存不构成客户端全量数据库。

搜索历史、书架及标题偏好只留在客户端或当前浏览器；可在界面清空搜索历史，不同步 Web。它们可能体现个人偏好，不进入源码、发布包或公共诊断。

Windows 记住密钥时只保存当前用户可解密的 DPAPI 密文；CLI 使用当前进程 `VN_LIBRARY_KEY`，不自动解密桌面凭据。密钥应独立安全保管，DPAPI 密文不能单独承担跨用户或重装恢复。

## 同步与状态

个人条目、游玩经历、收藏／分类、存在标记各有独立身份与修订。“曾玩过”“明确未玩”“未记录”与“本地已有”分开；安装／卸载不清除个人评价，Web 上报已有不证明当前电脑可启动。

离线原稿、原始编辑基准、待同步批次和写入回执保留在原服务作用域。回复丢失时按原 ID 和内容重试；明确冲突时保留原稿并重新读取。不要清空 JSON、重建设备身份或换批次 ID 来绕过冲突，也不要将另一服务的待提交文件手工搬来使用。

旧登记可通过 CLI 的预览／批准入口迁移为轻量索引，旧原件保留。不得混用旧客户端继续写原件；迁移后详情和未同步资料仍需备份，不能当作任意可删缓存。JSON 采用有界读取，大文件应使用明确迁移入口，不通过任意提高限额绕过校验。

## 备份与恢复

- **Web 个人库**：使用 Admin 完整 snapshot，保管数据库、已登记封面、实例和匹配镜像；密钥另存。快照包含已验证任务输入时，才可能离线恢复未完成任务。
- **客户端**：退出应用后保存整个数据根，包括稳定 ID、离线稿、详情和恢复证据。密钥另存，DPAPI 凭据不保证换用户可用。
- **游戏文件**：不在 Web 或客户端 JSON 备份内，单独保管。目录复原使用准确回执，并核对注册表、启动依赖及新增存档。
- **独立新库**：使用应用与官方公共资料包，生成新实例及新密钥；不用个人快照作公共分发。

完整恢复只写新目录，不覆盖活库、不删除在线 WAL／SHM。旧镜像不能写新 schema；升级和离线恢复见 [Docker 指南](DOCKER.md)。

## 源码与分发边界

仓库及可分发包只保留程序、通用配置、项目／架构／使用文档与许可。真实部署地址、账户、密钥、个人数据库、客户端 JSON、运维工作记录和临时验证材料放在库外。开发构建与日志默认写入仓库旁 `VndbCli.private`。

对外诊断优先使用桌面“导出脱敏启动报告”，只包含版本、阶段、耗时、错误类别和固定建议；不附原始数据或异常堆栈。提交或分发前可执行 `python -B scripts/check_repository.py --all-files` 检查仓库，扫描结果不能代替人工核对分享范围。
