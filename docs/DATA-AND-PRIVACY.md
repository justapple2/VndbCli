# 数据位置、隐私与备份

Web 保存完整资料库；桌面和 CLI 只使用本机 JSON。程序目录与数据目录独立，更新或移动可执行文件不应改变数据身份。

## Web 数据

| 内容 | 部署数据目录中的位置 |
| --- | --- |
| 作品、会社、发行版本、个人条目、评价与时间 | `data/library.db`；容器内 `/data/library.db` |
| 已缓存封面 | `data/covers/` |
| 稳定服务实例身份 | `data/service-instance-id` |
| 官方导入原包和任务输入 | `data/datasets/` |
| 完整备份 | `data/backups/` |
| 应用管理密钥 | 独立 `secrets/library_write_key`，只读挂载，不放入镜像或数据库快照 |

实际宿主目录由 Compose 挂载决定。SQLite 应放在 NAS 本机卷，客户端通过 HTTP API 访问，不通过共享文件夹直接写库。完整恢复需要数据库、封面、原实例、匹配镜像和独立保管的原密钥，步骤见 [Docker 手册](DOCKER.md)。

Web 只保存按精确条目和设备上报的存在布尔值，不保存游戏绝对／相对位置、EXE、安装包清单、组件目录树、注册表信息或整理回执。封面相对路径是服务自身缓存位置，与客户端游戏位置不同。

## 客户端 JSON

默认数据根为操作系统解析的“文档”下 `VndbLocal`；明确设置 `VN_DESKTOP_HOME` 可覆盖。文档目录可能被系统重定向，不应按用户名拼接路径。服务器地址与配置优先级见 [CLI](CLI.md#2-连接配置与数据根)。

| 内容 | 数据根中的位置 |
| --- | --- |
| 稳定设备身份 | `device.json` |
| 完整安装、组件、安装包关联与资料快照 | `local-library.json` |
| 明确迁移后的轻量安装登记、条目与详情引用 | `local-library.v2.json`；旧原件保持原样，检测旧程序写入 |
| 迁移后按内容摘要保存的完整资料 | `local-metadata/<SHA256>.json`；只在本机，不作为 Web 请求 |
| 按服务、精确条目隔离的按需详情缓存 | `servers/<服务地址摘要>/item-details/<条目ID摘要>.json` |
| 启动入口、参数 | `launch-profiles.json` |
| 显式观测范围、卷与根身份、开关 | `observation-settings.json`，默认关闭，仅本机 |
| 目录／入口／包元数据与待匹配候选 | `local-observations.json`，派生快照，最多32MiB；不读取游戏内容做哈希 |
| 整理／复原的观测协调标记 | `local-resource-intents/`，只含本机意图身份和完成状态，保留原恢复证据 |
| 服务器、转区工具、整理目标 | `desktop-settings.json` |
| 目录整理／复原证据 | `archive-runs/`、`organization-state/` |
| 注册路径修复备份 | `registry-repairs/` |
| 按服务区分的查询、待同步记录和回执 | `servers/<服务地址摘要>/`；查询根可独立配置 |

安装包按明确检索根和相对文件位置登记，只作为“已有”资源，不变成可启动安装。文件名匹配只是候选，不证明版本、完整性或安全性；不解压、挂载、安装或运行。根断开／不可读或文件变更时保持未知，不直接撤销先前存在标记；可读根下确认缺失才记为缺失。同一条目任一已登记安装或包存在，即可上报已有。

查询 JSON 可导出供 Web 导入；完整客户端根、目录扫描报告、注册表备份和移动回执不能上传 Web。公共目录的历史页缓存只支持原筛选／页码，不是桌面全库离线检索数据库。

查询作用域内的 `search-history-lookup.json`／`search-history-catalog.json` 仅存各20项显式搜索文字，单文件上限32KiB；可通过界面清理，不同步Web。`catalog-producers.json` 只保存该服务最近一次会社选择快照，128KiB、最多60项；离线须命中原关键词，不是个人登记或待导入内容。浏览器最近搜索保存在当前站点localStorage，各范围最多20项；可在页面清空。搜索文字可能包含个人偏好，完整客户端和浏览器数据均不应进入源码、发布包或公开诊断。

Windows 选择记住应用密钥时，桌面只保存当前用户可解密的 DPAPI 密文；CLI 使用进程环境中的密钥。不要把密钥写入普通 JSON、源码、命令历史或发布包。DPAPI 密文不能单独承担跨用户／重装恢复，应独立安全保管原密钥。

## 状态与恢复

“曾玩过”“明确未玩”“未记录”和“本地已有”彼此独立。收录公共资料或登记安装包不会创建游玩经历；重玩保留独立身份，已有资源不表示当前设备可直接启动。

备份客户端前退出程序，保留整个数据根及稳定 ID、未知字段、待同步原件和原操作回执。结果不明按原操作重试；409 先重读比较，不清空 JSON、重建设备身份或改批次 ID。换服务器时不手工搬移不明来源的待提交文件。

个人编辑的新原稿保存必要原值以提供字段对照，仍只在本机JSON；请求不会发送这份原值，旧稿缺少时显示未知。对照中的评价、备注和分类属于个人资料，不能当作公共诊断导出。本机`startup-diagnostics.json`仅保留最近一次启动的允许字段（版本、系统类别、阶段、时间、耗时、错误类别和固定建议，最多64KiB），不记录异常原文、堆栈、地址、路径或个人内容。它和原始本机资料均不进入源码／发布包。

普通配置及旧登记仍为8MiB有界读取；明确迁移入口最多读取256MiB旧登记，不以全局放宽限制处理增长。v2 权威索引最多32MiB／10000条作品，单个详情最多8MiB、当前引用的去重详情总量最多256MiB。书架聚合快照独立为64MiB；按服务的按需条目详情缓存最多1000项／256MiB，达到预算会提示人工归档，不自动删除。迁移中断留下的未引用资料不成为权威登记，也不自动清理；切换索引前会完整写入并核对引用。保留旧原件、未知字段及所有待同步和复原证据。`local-metadata` 中的离线未同步资料也必须备份，不能视为可任意删除的临时文件。

游戏移动与注册路径修复都有独立预览和确认。复原应使用对应完整目录回执，保留移动后新增存档；数据根备份并不包含游戏文件本身。迁移前后的注册表、快捷方式和安装依赖仍需逐项核对。

观测范围最多32个、浅层深度1–3、监听器最多64个、脏提示集合最多256项。发现最多保存5000个候选；每次发现枚举最多1024个目录／10000项，达到预算会降级提示，不扩展为整盘扫描。已登记资源每项最多复核8个组件目录、16个入口和32个内容锚点，常规检查只读元数据。配置与普通JSON仍遵守原8MiB上限，只有派生观测快照使用独立32MiB预算。未启用时不自动扫描游戏；候选不产生个人条目、启动配置或VNDB联网请求。根不可读／身份改变会保留上次设备存在标记。存在标记回传不包含这些路径、候选、指纹、启动状态或目录结构。
