# 桌面端使用说明

适用版本0.5.0，Windows x64自包含发布。桌面负责书架浏览、离线启动、本机登记／整理及个人资料同步；完整数据库只在Web。应用采用单管理密钥，无多用户权限体系。

## 1. 安装与首次连接

解压Desktop包到独立目录，保留整个目录，运行`Vndb.Desktop.exe`，无需另装.NET运行时。更新时解压到新目录，退出旧客户端后切换入口，不覆盖运行中的程序或文档数据目录。

进入「设置」，填写Web根地址，例如`http://nas.local:5187/`，输入应用管理密钥，点击「保存并应用」，按F5刷新。地址不能带子路径、用户名密码、查询或片段。管理密钥不是SSH密码／VNDB令牌；浏览可不填，资料补全、个人修改和同步需要它。

Windows凭据按Web地址、使用当前用户DPAPI加密保存。更换服务不发送原服务密钥；不要将凭据JSON复制给另一Windows用户当明文密钥使用。

启动阶段的配置、书架或会话数据错误会显示在状态栏，并停止后续初始化，保留原件供核对；不要为解决启动错误清空配置。聚合书架快照独立使用64MiB读写上限，安装目录和安装包位置仍从本机资料JSON读取，其他配置／查询及HTTP响应的上限不随之放宽。

### 标题与作品详情

在「设置 → 外观」选择日文优先、作品原始语言或罗马字／拉丁标题，并可附加日文副标题。个人标题覆盖优先；点击保存后保留在本机。此偏好只改变显示，不重命名游戏目录，也不修改启动参数。

作品详情将公共资料与来源、个人覆盖和游玩经历、本机安装与启动分区展示。VNDB 公共评分与个人评分各自独立。发行目录每次显示20项，可筛选已收录的语言、平台、标题或发行ID；明确区分官方／非官方、机翻、试玩／部分／完整和补丁，本机实际安装版本仍需自行确认。

关联区只显示资料中已记录的直接关联。点击关联只读取 Web 本库或当前服务作用域下的 JSON；缺资料时可回填作品ID，再明确执行查询。关联详情保持只读，返回后恢复原书架条目；不会借用同一作品其他个人版本的启动配置或评价。旧快照缺少关联字段会显示未知，可显式刷新作品。

## 2. 本机数据和备份

默认数据根为系统「文档」下的`VndbLocal`，与EXE位置无关。设置「本机数据与查询作用域」显示实际地址；系统文档可能被重定向，应以界面为准，不能使用NAS共享目录。

| 内容 | 边界 |
| --- | --- |
| 桌面设置、稳定随机设备ID | 本机JSON，升级保留 |
| 安装／合集组件、EXE／参数／工作目录、全局LE | 本机JSON，不上传Web |
| 整理／复原回执、注册表修复备份 | 本机私有证据，不当成导入文件 |
| 查询快照、pending、绑定与回执 | `servers/<规范Web地址的SHA256>/`；无服务为独立offline作用域 |
| 个人编辑／会话待同步稿 | 本机JSON，匹配Web回执后才确认 |
| 书架缓存与DPAPI凭据 | 按服务隔离，不替代权威库 |

`VN_DESKTOP_HOME`可指定明确的独立数据根；`VN_LIBRARY_CACHE`或设置中的查询根只改变查询JSON位置，仍按服务隔离，不移动设备ID和启动配置。普通使用保持默认即可。旧资料迁移先看诊断／预览、核对来源后确认；损坏或未知来源原件保留，不手动清空绕过保护。

备份时退出应用，保存整个本机数据根，密钥另存。只备份程序目录找不回安装路径。向他人提供诊断时，不附原始本机JSON、命令预览、注册表备份或个人稿件。

## 3. 书架与查询

「我的书架」「游玩记录」「查询作品」独立保留当前浏览条件、选择及翻页。可切换卡片／左侧小封面列表，使用搜索、会社／状态／本机存在筛选，以及添加时间、发售时间、会社、上次打开等下拉排序。首页「记住书架偏好」仅保存本机偏好。

单击只选择，Enter／双击打开详情，窄窗Esc关闭详情。打开详情不会自动扫描磁盘或启动游戏。右键／可见更多菜单提供直接启动、LE默认启动、打开目录、进入配置、本机登记和快速游玩编辑；不可用项需先补配置。

支持新版服务时，个人书架先读取轻量摘要，已玩分类来自服务端聚合，简介、备注、完整发行目录与游玩明细在打开详情时读取。未加载会明确提示；离线只能显示已缓存的详情，不将未加载记录当成“未玩”。旧服务继续使用原读取路径。刷新只有完整读取成功才替换快照，失败会保留已显示结果。

大量本机登记可使用 [CLI 的索引迁移](CLI.md#本机登记的轻量索引迁移)，把资料重字段从权威安装索引拆开。程序不会自动迁移现有登记；迁移前退出客户端并备份整个数据根。

F5刷新，Esc先处理编辑面板／详情，再取消操作。右上角日／月图标切换主题，设置可保存减少动画。Web外观偏好与桌面独立。

「查询作品」支持标题、别名及VNDB ID。默认先Web本地库，缺失由Web查询并入库；Web不可达时读本机快照或Core直连VNDB，生成可导入JSON。完全断网只能用已有快照。401、修订冲突、协议错误、上游限流不被当作Web断线静默回退。

## 4. 本机安装登记

安装包／镜像不作为安装目录。从「目录整理」的安装包区扫描文件名，明确查询／选择作品，预览确认后登记；也可从书架卡片菜单「登记安装包」选择准确条目。检索根与相对位置仅存本机JSON，Web只展示“本地已有”。支持zip、7z、rar、iso等常见包／镜像；分卷只建议首卷，不检查整套齐全，自解压EXE不自动识别为包。默认扫描深度3，可明确核对已登记文件。根断开、不可读或文件变更保持未知，详细数据范围见[数据与隐私](DATA-AND-PRIVACY.md)。

从详情「登记／重新核对本机安装」进入：

1. 明确选择完整游戏／合集目录，核对标题和会社；metadata只提供线索，不代替用户选磁盘范围。
2. 单作品选择准确Web条目；合集／特典保留完整物理容器，分别登记组件和相对位置。本篇、追加篇、不同版本不合为一条。
3. 核对预览后确认登记。登记不会移动文件或启动程序。
4. 「同步资料与存在标记」同步公开条目及布尔值；离线先保留稳定本机ID，收到匹配Web映射回执后才以真实ItemId同步presence。

Web只知道作品是否本机存在，不知道目录、EXE或合集结构。移动／盘符变化后显式重新核对，实际确认目录恢复后再恢复present，不为让按钮可用而手改缓存ID。

## 5. 启动配置与Locale Emulator

「本机启动」选择已有配置或「新增独立配置」，填写名称、启动程序、参数、工作目录及可选安装／组件关联，再「保存本机配置」。离线独立入口可以不关联Web。

「预览已保存命令（不启动）」和启动都使用左侧选中的**已保存配置**，右侧改动先保存。改变安装关联保留EXE／参数草稿，仅清除不属于新安装的组件；新增独立配置不删除旧配置。高级候选发现需手动点击，应排除config、卸载器、补丁等，始终核对准确游戏EXE。

包装器示例，全部为合成路径：

| 字段 | 示例 |
| --- | --- |
| 启动程序 | `F:\VN\Example Studio\Example Game\AlphaROMdiE.exe` |
| 启动参数 | `SiglusEngine.exe` |
| 工作目录 | `F:\VN\Example Studio\Example Game` |

不要把整条命令放进启动程序栏。含空格的单个参数加双引号，复杂参数可用高级JSON数组，如`["SiglusEngine.exe"]`。不会自动执行导入JSON中的命令或解析不明快捷方式，请明确配置EXE和参数，且不夹带应用密钥。

「设置」选择全局LE工具路径，读取配置并选择默认语言，保存并应用。高级项可手工输入GUID。之后书架或启动页选择「直接」／「LE默认配置」，无需逐游戏填写工具。配置只留本机，不改系统区域、不自动提权。LE不转换游戏自身语言版本，按游戏要求选择。

直接或LE启动不依赖Web及计时。包装器如果启动另一个实际游戏进程，计时需按会话页明确进程检查处理，不能仅凭包装器退出判断游戏已结束。

## 6. 迁移后的注册信息修复

展开「迁移后的注册信息检查／路径修复」，输入明确旧／新目录并预览。程序仅在受限厂商HKCU／HKLM Software范围查找匹配目录字符串。核对具体项、选择后先保存本机备份，再明确批准修改并验证；恢复使用对应备份及当前状态校验。

这是目录字符串修复入口，不是通用注册表编辑器／游戏重装器。权限不足、并发变化会停止，不自动提权或运行任意REG。备份不上传Web，其他安装依赖由用户另行处理。

## 7. 游玩、评价与同步

右键「快速更新游玩」或打开准确经历的编辑入口，选择既有经历／明确新建重玩，填写状态、日期、历史／手工分钟、评分、感想、备注1和备注2。重玩有独立PlayId，不能只按标题或VNDB ID覆盖某次经历。

未知时间／评分留空，不用0代替未知。手工基数、自动会话和人工调整分开保存，合计单独投影。修改既有记录保留未编辑字段；切换／关闭有未保存稿件时按提示处理。

「本机已保存」「Web已接收」「等待补全」「候选／冲突待核对」「已确认」含义不同。断网／结果不明保留原JSON及操作ID，重连按原操作重试；不要新建重复稿。409时保留原稿，显式重读当前记录比较。设置的「导入限额／最近逐项回执」是最多100行的已有回执快照，不是全部后台任务的实时监视器。

Web `/manage.html`导入metadata，`/sessions.html`导入活动／评价／会话JSON。先核对格式、限额与逐项结果；完整本机数据根、整理证据不能上传。

### 可选计时

「游玩会话」明确选择经历后开始／暂停／恢复／结束计时，基本启动不依赖计时成功。按准确PID／创建时刻／路径跟踪，不猜同名进程；包装器跟踪不明时人工检查。退游后结束记录并可编辑感想，异常／跨设备重叠可能待核对，不重复累计。

系统睡眠／休眠后继续运行由用户处理，可以事先暂停／结束；本版不承诺此场景自动恢复。

## 8. 目录整理与复原

设置明确源范围和同卷目标根，布局为`目标根/会社/游戏日文名`。「目录整理」先扫描／登记，再生成完整计划，核对路径、关联、兼容名和批准摘要，最后执行。条件变化或重扫使旧批准失效。

只对完整容器做同卷直接rename，保留游戏／特典内部结构，不复制、删除游戏、创建硬链接／目录链接或合并重名。已有会社布局优先保留，目录别名按[兼容命名](FILESYSTEM-NAMING.md)去不兼容符号，原始metadata及内部EXE不变。碰撞、歧义、身份变化停止。

中断使用原回执续跑；复原先预览当前完整容器，再按新摘要批准回迁，保留新增存档。证据只存本机。首次建议只选一个明确完整目录，核对后执行。

## 9. 常见问题

| 现象 | 处理 |
| --- | --- |
| 更新后没有原启动配置 | 核对实际数据根、Windows用户、VN_DESKTOP_HOME；先备份，勿清空JSON |
| 浏览正常但补全／同步失败 | 核对Web地址和应用密钥，401不自动回退 |
| Web显示本地存在但不能启动 | presence不提供EXE；在本机登记并保存准确入口 |
| 特殊符号目录打不开 | 先生成兼容命名计划，不随意改内部资源或EXE |
| 存在批次明确拒绝 | 读取状态→预览重新核对→批准→重试；结果不明保持原ID |
| JSON损坏／修订冲突 | 保留原件按来源／修订恢复，不重置为空书架 |

详细数据位置和备份范围见[数据与隐私](DATA-AND-PRIVACY.md)。目录扫描、移动与游戏启动由用户明确选择和确认。

## 10. 发行版本

在查询页填写作品ID（如v17），点击“按作品ID查询发行版本”；可选刷新已缓存版本，来源沿用当前选择。完成后打开结果详情，查看版本、语言（含机翻）、平台、日期、官方/非官方、补丁和完整度；结果可导出JSON。个人书架详情显示已保存目录；打开详情本身不发起联网查询。未来日期、试玩或补丁不保证本机游戏已支持该语言。

## 11. 个人状态与公共资料

“未记录”表示还没有关联的游玩经历；“未游玩”筛选只包含明确not_started且没有玩过历史的条目。“曾玩过”沿用现有规则，含游玩中、玩过、完成、搁置和放弃；重玩待开始不清除以往玩过的事实。具体经历和评价仍分别保存。状态不明或关联有歧义显示待核对。

公共查询结果不会自动进入个人书架；详情标明公共资料/个人书架范围。客户端JSON中的明确游玩记录为桌面状态来源，不用记录条数推断玩过，也不因Web返回一个更新统计就覆盖更近的离线个人修改。“本机有副本”继续依据本机安装登记，Web的存在上报不能当作本机可启动的证明。

## 12. 公共资料目录

可重置筛选，按Ctrl+Enter或“应用筛选并浏览”读取；条件修改会提示尚未应用，翻页沿用最后成功条件。首末页、无选择与加载中的按钮按状态禁用；首次／空结果有提示。卡片显示选中边框，读取失败保留原页，切换连接后不接收旧回复。

新增独立目录入口，个人书架仍默认。点击应用筛选后，在Web已收录公共库中按发行语言／类型／平台、会社ID和排序全局检索；翻页沿用已应用条件。卡片／列表含个人汇总、独立存在标签和资料来源。选择后可明确读取详情，个人编辑仍走原流程。NAS不可达时仅回显同筛选／页码的历史JSON；「仅本机历史页JSON」不访问网络。目录JSON位于既有查询作用域的public-catalog子目录，不是客户端数据库或待同步批次，详见[公共资料目录](CATALOG.md)。

## 13. 本机变化观测

默认关闭。进入设置的“本机变化观测／待匹配候选”，选择游戏根或安装包根，设定布局深度，加入范围草稿。游戏“会社／游戏”布局用2层；游戏直接位于根下用1层。核对范围、勾选确认后保存；该基线只记录元数据，不重新信任变化后的程序。首版自动观测支持本机NTFS，网络共享、映射网络盘及其他文件系统使用原手动核对流程。

只在客户端运行时监听，不安装系统服务或自启任务。同一数据根只启用一个观测宿主；第二窗口不重复监听。只观察管理根和有限会社／容器层，不监听整个游戏内部写入；最多64个监听器，其余范围以周期浅层核对补齐。启动补查关闭期间的新目录／包，约每10分钟兜底；深层EXE变化可能在打开／启动前或下次核对时发现。“立即检查本机变化”可在后台监控关闭时使用已保存的管理范围。

缺失先显示待确认，至少间隔10秒再确认；根不可读、卷／目录身份变化和证据不足均为未知。只有EXE丢失但游戏内容仍在，不撤销拥有状态；入口不可读或元数据变化会阻止该入口快速启动。重新安装／替换目录后，先明确重新登记，再按需重新保存启动程序；观测不会更新程序哈希、参数或LE配置。多个入口分别复核；多组件容器无法安全独立判断时整体待核对，不自动拆分合集。

新目录和包先作为待匹配候选，稳定约15秒后可进入登记草稿，仍需查询并选择准确作品、预览确认。不会自动访问VNDB、把文件名当作准确关联、解压或安装。忽略只改变候选标记，文件保持原样；页面最多展示前100项候选／提示。新安装持续写入时继续等待，不以稳定标记证明安装完成。

在管理范围内发现与原目录／包相同的物理身份时，展示旧位置→新位置的只读映射预览，保持原登记为未知，避免把手动改名误报为卸载。不会新建重复安装或自动改写原路径、启动配置；路径关联的实际修改仍需人工处理。无法确认身份或发现范围达到预算时保留待核对，不能凭相似文件名认领。更换设备身份后，应归档绑定旧设备的派生观测快照再建立新基线，不能清空权威登记或恢复证据。

本机实际状态变化合并到现有约60秒的同步周期；断网保留JSON，结果不明按原批次重试，明确冲突保留原稿。Web只接收本设备的存在布尔值；已玩、评价和时间不会随安装变化清空。整理／复原未完成时暂停解释相关安装的缺失；旧整理意图在首次观测时进行一次有界流式核对，损坏或超过1000条时提示人工处理，原件保留。

监听事件可能重复或丢失，因此事件只触发实际核对；参考 [Microsoft FileSystemWatcher 说明](https://learn.microsoft.com/en-us/dotnet/api/system.io.filesystemwatcher.error?view=net-10.0)。停止监控或关闭应用会释放监听器与后台任务，最后登记和恢复证据继续保留。

## 14. 筛选、快捷视图与最近搜索

书架提供会社名称、游玩情况和本机资源筛选，可组合使用；条件标签可逐个移除，也可清除当前视图的条件。选定会社暂时没有结果时保留条件，不自动扩大范围。书架、已玩页和本次查询分别保留会话内页码、选择及卡片／列表滚动位置；更换服务后清空浏览状态。查询结果筛选只影响本次返回；全库检索使用“公共资料目录”，先由Web筛选再分页。

快捷视图复用相同条件：本机已安装、仅有安装包、缺失／待核对、本机已有且未玩、游玩中、未记录。“未玩”只含明确未开始且没有玩过历史的记录；“游玩中”等具体状态命中任一有效关联经历，重玩或后续完成不会抹去其他经历。资源消失不改变游玩分类。

卡片及列表分开显示个人经历、本机资源、启动状态和Web上报。Web上报已有不证明此电脑有安装；确认资源存在也不证明可运行。“可复核启动”只筛选已有安装和保存入口且观测未阻断的条目，启动时仍执行文件与配置保护。右键失效入口附有原因，配置、登记和个人编辑仍使用原流程。

公共资料目录可输入会社名称或ID，明确点击“查找会社”，从Web已收录会社中选择；最多60项，必要时缩小关键词。选中只修改草稿，点击浏览或Ctrl+Enter后生效，不查询VNDB。离线仅回显同一服务、同关键词的已缓存会社选项。

查询页和公共目录的“最近搜索”只记录显式提交的非空关键词，各最多20项，按服务分别保存；可删除选中或清空。选择历史后点击“回填，不查询”只填入输入框，仍需显式查询／浏览。历史损坏时保留原文件并提示，不阻断查询。Web也有同源浏览器历史及少量快捷视图；它仅按上报布尔值筛选，不提供安装／包／启动判断。浏览器返回不会自动重发缺资料时的VNDB联网收录请求。
